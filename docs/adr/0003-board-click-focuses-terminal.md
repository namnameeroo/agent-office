# 칠판을 누르면 서버가 그 세션의 터미널을 앞으로 가져온다

**결정**: 칠판(상태판)을 누르면 화면이 `POST /api/focus { pid }`를 보내고, 서버가 그 세션이 도는 터미널을 앞으로 가져온다(T13). **[사용자 2026-10-27]** "구현할 수 있는 데까지", 외부로 가는 동작이라 hover 표시를 둔다.

| 터미널 | 알아내는 법 | 앞으로 가져오는 법 | 확인 |
| --- | --- | --- | --- |
| Orca | 세션 프로세스 환경 변수 `ORCA_TERMINAL_HANDLE` | `orca terminal switch --terminal <handle>` 뒤 `open -b com.stablyai.orca` | 식별자 19개가 `orca terminal show`로 유효함을 확인. 사용자가 칠판을 눌러 그 탭이 앞으로 오는 것을 확인(2026-10-28) |
| Ghostty | `TERM_PROGRAM=ghostty`. 창은 AppleScript로 터미널 목록(id·작업 폴더·제목)을 읽어 같은 폴더 + 같은 제목(앞 상태 기호를 뗀 것)으로 고른다 | AppleScript `focus` + `activate` | 같은 폴더 Ghostty 세션 둘 사이를 오가며 앞 창 제목이 바뀜을 확인 |
| 그 밖(번들 id가 있는 앱) | `__CFBundleIdentifier` | `open -b <id>`. 창은 고르지 못하고 앱만 앞으로 | 미확인(해당 세션 없음) |

- 환경 변수는 `ps eww -o command= -p <pid>`로 읽고 위 세 키만 남긴다. 다른 값(토큰 등)은 버리고 화면에 주지 않는다.
- Ghostty에서 창을 하나로 고르지 못하거나(같은 폴더에 제목이 안 맞는 창이 여럿) 그 밖의 앱이면 앱만 앞으로 가져오고, 화면 위에 그 이유를 4초 띄운다. 실패도 같은 자리에 이유를 띄운다.

**이유**: 대시보드에서 기다리는 팀장을 보고 바로 그 터미널로 가는 것이 이 화면의 다음 동작이다. ADR 0001의 "읽기만 한다"는 Claude Code 설정·파일을 바꾸지 않는다는 뜻이고, 이 결정도 그것은 지킨다. 다만 서버가 처음으로 화면 밖(다른 앱)을 움직이므로 다음으로 범위를 묶는다.

- 포커스만 옮긴다. 터미널에 입력을 보내지 않는다(`orca terminal send`, Ghostty `input text`를 쓰지 않는다).
- 같은 화면에서 보낸 POST만 받는다. Host 검사(DNS 리바인딩)에 더해 `Origin`이 `http://<Host>`와 같아야 한다. 다른 사이트의 폼·fetch는 여기서 막힌다. 본문은 256바이트까지다.
- pid는 서버가 지금 수집한 세션 것만 쓴다. 명령은 `execFile`(셸 없음)에 고정 인자로 넘기고, 세션에서 읽은 값(Orca 식별자·번들 id·Ghostty id)은 모양을 정규식으로 검사한 뒤 쓴다.

## Considered Options

- **더블클릭(T13 첫 안)**: 실수로 누를 일이 적다. 사용자가 한 번 누르기로 정했다. 방 선택은 칠판 밖(방 나머지)을 누른다.
- **브라우저에서 URL 스킴(`orca://`)으로 열기**: 서버가 명령을 실행하지 않아도 된다. 대신 Orca의 터미널 단위 스킴이 확인되지 않았고 Ghostty에는 없다.
- **Ghostty를 폴더만으로 고르기**: 단순하다. 대신 같은 폴더에서 세션 여럿을 돌리면(실제로 셋) 엉뚱한 창으로 간다.
- **Ghostty·그 밖 앱은 지원하지 않기**: 코드가 줄어든다. 대신 실데이터 23개 중 4개(Ghostty)가 빠지고, 앱만 앞으로 가져오는 것도 쓸모가 있다.
