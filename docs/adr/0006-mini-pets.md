# 미니 모드는 세션마다 바탕화면 위에 떠 있는 캐릭터 창이다 (0005의 띠를 대체)

> **읽는 법 (2026-11-12)**: 이 문서는 결정이 쌓인 순서대로 적혀 있어, 아래 표와 앞쪽 절에는 뒤 절이 바꾼 내용이 남아 있다. 지금의 모습은 바로 아래 "지금의 모습" 절이 기준이고, 어긋나면 그 절이 맞다.

**결정**: 미니 모드에서 휴면이 아닌 세션마다 **투명·비활성 패널 창**(`/mini?pid=N`, 기본 80×60)을 하나씩 띄운다. 얼굴·이름표를 끌어 옮기고(위치 기억), 더블클릭하면 터미널이 앞으로 오고, 우클릭하면 네이티브 메뉴가 뜬다. 서버가 끊기면 전부 반투명·정지. **[사용자 2026-11-11]** "각 세션들 캐릭터가 floating처럼 보여야 하고, 하나씩 옮길 수 있어. 이름표나 얼굴은 드래그, 두 번 더블클릭하면 터미널. 우클릭하면 컨텍스트 메뉴." ADR 0005의 하단 띠는 브라우저 `/mini` 미리보기로만 남는다. 설계: [specs/2026-11-11-mini-pets-design.md](../superpowers/specs/2026-11-11-mini-pets-design.md).

## 확인한 것 (2026-11-11, 이 PC)

- `node --test` 109개(기하 `pets.mjs` 4개 추가). `node --check` 전 모듈.
- `PORT=4599 AGENT_OFFICE_SCREENSHOT_MINI=…`(바탕화면 `screencapture`): 휴면 아닌 세션 3개가 바닥 왼쪽부터 24·112·200에 80×60(말풍선 없음)으로 떠 있고 사이로 뒤 앱이 보인다. 디버그 `[fit]` 로그로 bounds 확인.
- **미확인(사용자 확인 필요)**: 끌어 옮기기와 위치 복원, 더블클릭 → 터미널, 우클릭 메뉴, 펼친 말풍선의 창 성장·`moveTop`, 끊김 반투명, `Cmd+Shift+M`·Dock 클릭 복귀, 비활성 패널이 실제로 키 입력을 안 뺏는지. 캡처 시점에 사용자가 띄워 둔 이전 빌드(띠)가 바닥을 덮고 있어 캐릭터가 다른 창 위에 오는지도 재실행 후 확인.

## 함정

- `type:"panel"` 창은 만들 때마다 AppKit이 `NSWindow does not support nonactivating panel styleMask 0x80`을 창당 3번 찍는다(`focusable:false`를 빼도 같음 — 실측). Electron의 panel은 NSWindow 서브클래스가 styleMask getter에 비활성 비트를 얹는 우회라, 다른 옵션(`closable:false` 등)이 styleMask setter를 부를 때마다 AppKit이 그 비트를 거부하며 경고한다. 창은 만들어지고 bounds도 맞다. 실제로 에디터 포커스를 안 뺏는지는 사용자 확인 항목.
- `transparent:true` 창에서 페이지 `body` 배경도 투명이어야 한다(`body.pet { background: transparent }`). 띠 CSS의 `#bar` 배경도 덮어야 한다.
- 펫 모드 `.cell`의 말풍선 줄은 `auto`(말풍선 없으면 0). 36px 고정이면 창이 96px이 되어 위 투명 여백이 클릭을 먹는다.
- 캡처 검증은 `webContents.capturePage`로 안 된다(창 하나씩). `screencapture -x`로 바탕화면을 찍되, 다른 Agent Office 인스턴스가 떠 있으면 가려진다.

## Considered Options

- **투명 창 하나 + 클릭 통과 토글** — hover 추적 IPC가 필요하고 끌기 구현이 복잡. 세션이 15개를 넘기 전까진 창 하나씩이 더 싸다.
- **`focusable:true` 일반 창** — 끌 때마다 앱이 활성화되어 에디터 키 입력을 뺏는다(빌더 검토).
- **`-webkit-app-region: drag`** — 더블클릭을 못 받는다.
- **메뉴의 터미널 포커스를 메인이 fetch** — 가능하지만 렌더러의 기존 경로가 있어 불필요.

## 2026-11-11 추가 · 디자인 v2

모습은 [specs/2026-11-11-floating-design-v2.md](../superpowers/specs/2026-11-11-floating-design-v2.md)(디자인 서브에이전트, 목업 `wireframes/floating-v2.html`)를 그대로 구현했다(커밋 7ce779f). 잉크 표찰 이름표(크림 테두리·상태 점·최대 120, 호버 240), 기다림만 머리 위 빨간 표지판 `! 7m`(5분부터 이름표 빨강, 15분부터 깜빡임), 말풍선 테두리는 기다림이면 빨강, 펼침 머리글 "전문 · 누르면 접힘", 호버 반전·끌기 들림·더블클릭 폴짝·등장 낙하, 끊김은 반투명+무채색+정지. 칸 간격 128, 기본 창 70, 바닥 줄이 차면 100px 위 둘째 줄. 창 크기는 `ResizeObserver`가 `.cell`을 따라 `fit`한다. 상호작용 규칙·창 옵션·위치 파일은 그대로.

- 확인: `node --test` 111, 디버그 `[fit]`로 창 105~126×70(이름표 폭에 따라), 바탕화면 캡처에 표찰·점이 보임. 호버·끌기·메뉴 피드백은 사용자 확인 항목.
- 함정: 띠 모드 CSS가 펫 모드에 새어 들어오므로(같은 `.cell`·`.name`) 제안 CSS는 `body.pet` 접두로 스코프하고 `width:auto`·`position:static`으로 되돌렸다.

## 2026-11-11 추가 · 글자는 시스템 글꼴 11px

펫 모드의 말풍선·이름표·표지판 글자를 PF스타더스트 Bold 12px에서 시스템 글꼴(`-apple-system`, Apple SD Gothic Neo) 500 11px로 바꿨다. 테두리(box-shadow)와 캐릭터는 픽셀 그대로다.

- 이유: 미니 모드는 글자가 작아야 하는데, 픽셀 글꼴을 10px로 줄이면 한글·숫자 획이 뭉개졌다(2× 캡처에서 "켰습니다"·"7m" 판독 불가). 시스템 글꼴은 10·11px 모두 또렷했다.
- 확인: agent-browser 2× 캡처로 4안(픽셀 12·픽셀 10·시스템 11·시스템 10) 비교. 바꾼 뒤 이름표·표지판 높이 16px 그대로, 글자 잘림 0(`scrollHeight - clientHeight`).
- 함께 지운 것: "…"만 Galmuri에서 가져오던 `PFDots` @font-face(픽셀 글꼴을 안 쓰니 필요 없다).
- 띠 모드(`/mini`, pid 없음)와 큰 창은 그대로다.

## 2026-11-11 추가 · 미니 상태에서 함께 보이는 정보

큰 창을 열지 않고 "누가 나를 왜 기다리나 · 얼마나 됐나 · 어느 일이었나"를 판단할 수 있게 했다. 새로 모으는 값은 없고 `/api/state`에 이미 있는 값만 쓴다.

| 언제 | 무엇 | 어디 |
|---|---|---|
| 늘 | 이 상태로 얼마나(`7m`·`5h`·`5d`, 단위 하나) | 이름표 끝(흐리게) |
| 기다릴 때 | 왜 기다리나(`! 승인`·`! 질문`·`! 답 필요`) | 표지판. 전에는 `! 7m`이었고 시간은 이름표로 옮겼다 |
| 0.4초 올려둘 때 | 위치(구역·worktree·브랜치) / 요청(내 마지막 요청 첫 줄) / 지금(작업 중일 때 최근 동작) / 링크(종류별 최신 PR·Jira·artifact 이름) | 맨 위 쪽지(232px, 값은 두 줄까지) |

- 쪽지는 누르면(끌기·메뉴) 접히고, 말풍선을 펼친 동안은 안 뜬다. 창이 캐릭터 크기라 `documentElement`의 mouseenter/leave가 곧 올려둠이다.
- 이름표는 `justify-self: start` + `min-width: 80px`로 얼굴 밑에 고정했다. 가운데 정렬이면 쪽지·말풍선으로 칸이 넓어질 때 이름표가 얼굴에서 밀려났다.
- 확인: `node --test` 114 통과(`signText`·`peekLines`·`elapsedShort`). agent-browser 2× 캡처로 작업 중·쪽지·승인 대기·질문 대기 16분을 봤다(대기 상태는 `fetch`를 가로채 만들었다).
- 미확인: 실제 Electron 패널 창에서 올려둠 → 창 커짐 → 벗어남이 깜빡임 없이 도는지. 쪽지의 링크는 글자만이다(누를 수 없다).

## 2026-11-11 추가 · 말풍선은 늘 뜨고 최근 응답을 말한다

미니 모드만 띄워 둔 채로 세션별 최근 응답을 볼 길이 없었다(말풍선은 기다릴 때와 끝난 지 5분 안에만 떴다). 그래서 말풍선을 늘 띄운다.

- 글: 기다릴 땐 무엇을 승인·답할지(`bubble`), 그 밖엔 가장 최근에 한 말 첫 줄(`said`). 지금 돌리는 도구는 쪽지의 "지금"이 맡는다.

- **새 캐릭터 자리**(다른 세션, `23d1073`): 새 세션이 기존 캐릭터 왼쪽·위에 생기거나 겹치던 것을 고쳤다. 원인은 "바닥 왼쪽 첫 빈칸" 규칙이 휴면으로 빈 자리를 새 캐릭터에게 주고, 빈칸 판정이 열린 창만 봐서 휴면 세션의 저장 자리를 남에게 준 것이다.
- 확인: `node --test` 138 통과, `npm run smoke` ok 42 / FAIL 0(배치 수정 포함 상태에서 재확인, 이 PC). 띠 제거는 25개 상황에서 rect·글자·창 크기가 전후 동일.
- 미확인: 실제 보조 모니터, 사람이 직접 하는 끌기·클립보드·브라우저 열기(smoke는 합성 입력 + 가로채기), 오른쪽 끝에서 창 폭이 바뀌는 순간의 한 프레임 깜빡임, 숨긴 동안 새로 생긴 창의 폴링.
- 하지 않은 것: 창 구조 재설계(세션마다 렌더러 약 81MB — 창 하나로 합치는 것은 별도 결정).
